# Spanish-Correct WER Normalization Protocol

The Quality Benchmark reports every WER metric in two lanes for each Workload Item and for the run-level aggregate. The Raw Metric Lane scores the Reference STM and Hypothesis STM text verbatim. The Normalized Metric Lane scores both sides after passing them through the Basic Text Normalizer vendored from OpenAI Whisper: bracketed and parenthesised content removed, text lowercased, markers/symbols/punctuation mapped to spaces, whitespace collapsed, and **diacritics preserved**. The normalizer is applied identically to reference and hypothesis, so the lane compares like with like. DER belongs to neither lane — it scores speaker time rather than text — and is reported once, alongside the Raw Metric Lane.

This replaces the previous normalization step, which stripped ASCII punctuation with `str.translate` and collapsed whitespace. That step was invented locally rather than adopted, so the numbers it produced were not comparable to any published Spanish WER, and the project had no way to distinguish a real quality improvement from a shift in the yardstick. The Basic Text Normalizer is the protocol OpenAI used to report Whisper WER for every non-English language, which makes the Normalized Metric Lane directly comparable to published figures for the models this project evaluates.

Diacritic preservation is the load-bearing part of the decision, not an incidental default. `BasicTextNormalizer(remove_diacritics=True)` collapses `está` onto `esta` and `año` onto `ano` — distinct Spanish words with distinct meanings. A hypothesis that drops accents would then score as correct, and reported error would be silently understated in exactly the direction that flatters the pipeline. The Quality Benchmark therefore constructs the normalizer with the default `remove_diacritics=False` and never exposes a setting to change it.

Whisper's `EnglishTextNormalizer` is rejected outright, for any language. Its spelling table, contraction expansion, number and currency handling, and British/American spelling map are English-specific; applied to Spanish they corrupt reference and hypothesis text in ways that neither cancel out nor stay measurable. It is not vendored at all, so it cannot be reached by accident.

Normalization is not neutral, which is why both lanes are always reported rather than the normalized lane replacing the raw one. The normalizer discards punctuation and casing, so a regression in either — a pipeline that stops emitting Spanish interrogative punctuation, or one that loses sentence capitalization — is invisible to the Normalized Metric Lane. The Raw Metric Lane exists to catch precisely that class of regression. The rendered report labels each table with the lane that produced it, so no figure can be read without knowing its protocol.

The normalizer is vendored into `coro/bench/normalizers/basic.py` rather than added as a dependency. It is roughly sixty lines of MIT-licensed code, and the upstream package that ships it (`openai-whisper`) pulls in Torch and a tokenizer stack the benchmark does not otherwise need. Vendoring is consistent with the dependency hygiene applied elsewhere in the project, and it pins the protocol: an upstream change to the normalizer cannot silently move reported numbers. The vendored module carries its provenance and licence attribution in its docstring. `split_letters` is retained from upstream for fidelity, with its `regex` import deferred into the branch that uses it, so the benchmark takes on no import-time dependency for a code path Spanish and English scoring never exercise.

Considered alternatives: keeping the punctuation-stripping step (rejected — not a recognised protocol, and the reason this decision is being recorded); depending on `openai-whisper` for the normalizer (rejected — a Torch-sized dependency for sixty lines, and an unpinned protocol); depending on `jiwer`'s transform pipeline (rejected — it is a toolkit for assembling a normalizer, not the published Whisper protocol, so it would reproduce the original problem of a locally invented yardstick); reporting only the normalized lane (rejected — hides punctuation and casing regressions); and applying normalization when the STM files are written rather than at scoring time (rejected — the Reference STM and Hypothesis STM are durable artifacts that other tooling reads, and destroying their text would make the Raw Metric Lane unrecoverable).

Benchmark figures recorded before this decision are not comparable to figures recorded after it. Comparisons that cross this boundary must be re-run, not reused.
