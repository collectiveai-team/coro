# Published API Contracts

> **Status:** Amends **ADR 0001 (Package and API Surface)**. The Supported Endpoint Set defined there covers the *product* surface; this ADR adds a Contract Surface alongside it. ADR 0001 otherwise stands.

Coro publishes its machine-readable contracts from the running app: OpenAPI 3.1 at `/openapi.json` for the request/response surface, AsyncAPI 3.0 at `/asyncapi.json` for the SSE event surface, and one Scalar reference at `/docs` rendering both. FastAPI's Swagger UI and ReDoc are switched off, because neither can render AsyncAPI at all and running two doc UIs for one server is the cost this change exists to remove.

Both contracts are **generated, never authored**. FastAPI builds the OpenAPI document from the route decorators and Pydantic models. The AsyncAPI document is built by `coro.api.asyncapi` from the same types the SSE writer serialises: payload schemas come from the `TranscriptDeltaEvent` / `TranscriptDoneEvent` dataclasses and `OpenAIErrorResponse`, the event discriminators come from the dataclass fields that are `init=False` (no caller can vary them, so they are envelope constants and are published as `const`, not as defaults), and the terminator frame is pinned to the `SSE_TERMINATOR` constant the writer emits. A field added to a wire type therefore appears in the published contract with no edit to the document builder.

That builder exists because nothing generates it for us. FastAPI emits nothing into OpenAPI for a streaming response body, and FastStream — the usual AsyncAPI generator — derives its document from *broker* decorators, of which coro has none. Only the channel skeleton is declared by hand: the address, the direction, and the prose. The address is the one hand-written value that can drift from reality, so a test pins it against the paths in the generated OpenAPI document rather than trusting it.

The exported documents are **build artifacts**, gitignored and never committed. CI exports both, runs `redocly lint` over them (one MIT tool covers both specs) and runs `oasdiff` against the base ref to fail a PR that removes or narrows part of the REST contract.

Those two jobs deliberately run in different environments. The lint-and-publish export reuses the fully-installed test environment, so the artifact is byte-for-byte what the deployed server serves, version and license included. The breaking-change gate instead installs only the `contracts` dependency group — the web layer, no project, no ML stack — because exporting a document needs `fastapi` and little else, and installing ~2 GB of CUDA wheels to serialise two JSON files is not a cost worth paying on every PR. With no project installed there is no distribution metadata, so those two exports carry no version or license; that is harmless because both sides of the diff are produced the same way, and `oasdiff` is comparing structure, not provenance. It does mean the gate would not notice a *dependency*-driven schema change, which is the price of the shortcut. Committing the export was rejected: `openapi.json` is a large generated blob that changes on every model edit, so it would be an unresolvable merge conflict on every schema PR, paid for a benefit — reading the contract without running the service — that only an external consumer needs. Not exporting at all was also rejected, because the breaking-change gate is most of the value. The AsyncAPI half has no comparable diff tool (`@asyncapi/diff` has been unreleased since 2024-12), so events are linted but not yet diffed.

The Scalar bundle is pinned and self-hosted. The image build fetches the pinned bundle into the installed package, and a source checkout with no bundle falls back to the *version-pinned* CDN URL so `uv run coro` needs no build step. The 3.7 MB bundle is not committed: it is minified JS with no business in a Python repo's history, and it exceeds the repo's own 750 KB added-file limit.

Self-hosting is only worth anything if the *page* also calls nothing out, so four upstream defaults are overridden. `scalar_js_url` defaults to an unversioned jsDelivr URL, re-resolved on every page load with no SRI. `telemetry` defaults to `True`. `agent` defaults to Scalar's hosted AI chat, which is enabled by default on localhost and — per Scalar's own configuration docs — uploads the served document to `api.scalar.com` on the first message, so anyone who opened `/docs` could hand this server's API surface to a third party. `with_default_fonts` defaults to `True`, pulling Inter and JetBrains Mono from `fonts.scalar.com` on every load. With all four overridden, loading `/docs` contacts the serving origin and nothing else, which is verified by test and was confirmed in a browser. The `api-docs-scalar-hardened` ast-grep rule fails the build if the bundle URL, telemetry or agent default is ever accepted; it extends the upstream rule, which guards only the first two.

`show_developer_tools` is deliberately left at its `"localhost"` default: it is local-only UI chrome that sends nothing anywhere.

Two limitations are accepted rather than papered over. `redocly lint` reports `security-defined` against both documents; coro genuinely ships no authentication, so the finding is a true statement about the API and is tuned to `warning` in `redocly.yaml` — to be promoted back to `error` if an auth scheme lands. And the published response schemas are thin: `/health` declares no `response_model` and the transcription route declares `response_model=None` for a union that varies by `response_format`, so neither documents its success shape. That predates this change and is left as a separate concern; this ADR covers exposing and validating the contract, not enriching it.

Considered alternatives included keeping Swagger UI and adding Scalar at a second path, hand-authoring the AsyncAPI document, committing the exports with a drift check, vendoring the Scalar bundle behind a raised file-size limit, and modelling the SSE stream as OpenAPI responses only. The chosen shape keeps one documentation URL for two contracts, keeps every schema derived from the code that produces it, and keeps generated blobs out of git.
