## Directive

`prek.toml` has a hook with the id `promtool-check-metrics`, so that one scrape of `GET /metrics`
passes `promtool check metrics` before a change to the metrics is committed, and on every CI run.

## Why

The exposition is generated by the running app, not tracked, so no linter of the source sees it.
A gauge named with `_total`, a counter without it, a metric with no help text or a name that is not
snake case still scrapes, and Prometheus stores it. The mistake shows up later, as a `rate()` over
a gauge or a dashboard query that matches nothing, and renaming a published metric breaks every
query and alert that names it. promtool is Prometheus's own checker of these conventions.

## Exceptions

A checkout with no `coro/api/metrics.py` publishes no metrics. `external-config` skips the rule
unless that file exists.

## Tool

[promtool](https://prometheus.io/docs/prometheus/latest/command-line/promtool/) ships with
Prometheus. `promtool check metrics` reads the text exposition from stdin and exits non-zero on a
problem. `scripts/export_metrics.py` builds the app with a runtime whose ASR Adapter has an
admission controller, so every metric family appears, and writes one scrape to a file.

promtool runs from the Prometheus image, pinned by version and digest, so the hook needs Docker.
A hook of `language = "golang"` cannot build it instead: `go install
github.com/prometheus/prometheus/cmd/promtool@<version>` refuses a module whose `go.mod` has a
`replace` directive, and the `go.mod` of Prometheus v3.15.1 has one.

## Configuration

The hook in `prek.toml`, as `config/prek.toml` of this rule holds it. Its `files` lists what shapes
the exposition: the route, the app, the admission controller, the export script and the lockfile,
which pins `prometheus-client`. CI runs it through `prek run --all-files`. `external-config`
checks that a hook with the id `promtool-check-metrics` is there.

## Do

```python
GaugeMetricFamily(
    "coro_asr_inferences_queued", "ASR inference calls waiting for a permit.", value=3
)
CounterMetricFamily("coro_asr_inferences_rejected", "ASR inference calls rejected.", value=1)
```

## Don't

```python
GaugeMetricFamily("coro_asr_inferences_queued_total", "ASR inference calls waiting.", value=3)
```

promtool reports `non-counter metrics should not have "_total" suffix`.

## Suppression

promtool has no suppression. Fix the metric, or remove the hook and switch the rule off in
`botica.toml` with the reason.
